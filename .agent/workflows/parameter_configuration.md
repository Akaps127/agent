# 4대 파라미터 설정 및 사용 가이드

이 문서는 공고문 생성 시 사용되는 4대 파라미터(계약법 구분, 계약 유형, 입찰 방법, 낙찰자결정방법)의 설정 및 사용 방법을 설명합니다.

## 📋 파라미터 개요

### 1. 계약법 구분
- **국가계약법**: 중앙행정기관 및 중앙정부 소속 기관이 체결하는 계약
- **지방계약법**: 지방자치단체가 체결하는 계약  
- **자체기준**: 특수법인이나 공공기관의 자체 계약 기준

### 2. 계약 유형
- **공사**: 건설공사 등 시설물 건축/설치
- **용역**: 일반 용역 서비스
- **물품**: 일반 물품
- **물품제조**: 제조를 통한 물품 공급
- **물품구매**: 기성품 구매
- **외주용역**: 외부 전문가를 통한 용역
- **학술연구용역**: 학술 연구 관련 용역
- **시설관리용역**: 시설 유지보수 및 관리
- **전문용역**: 전문 분야 용역
- **기술용역**: 기술 관련 용역

### 3. 입찰 방법
- **일반경쟁**: 불특정 다수를 대상으로 하는 경쟁입찰
- **제한경쟁**: 참가자격을 제한하는 경쟁입찰
- **지명경쟁**: 특정 업체를 지명하여 경쟁시키는 입찰
- **수의계약**: 경쟁 없이 계약상대자를 선정

### 4. 낙찰자결정방법
- **소액수의**: 일정 금액 이하의 소액 계약 (최저가 낙찰)
- **적격심사**: 가격과 품질을 종합 평가 (적격심사기준표 적용)

## 🔗 조건부 로직 규칙

### 핵심 규칙: 소액수의 ↔ 수의계약 연동

**규칙 1**: 낙찰자결정방법이 **'소액수의'**일 경우
- 입찰방법은 **자동으로 '수의계약'**으로 설정됩니다
- 사용자가 다른 입찰방법을 선택할 수 없습니다 (UI에서 비활성화)

**규칙 2**: 낙찰자결정방법이 **'적격심사'**일 경우
- 입찰방법으로 '수의계약'을 선택할 수 없습니다
- 일반경쟁, 제한경쟁, 지명경쟁 중 선택 가능합니다

## 🛠️ 구현 위치

### 백엔드 (Python)

#### 1. `src/parameters.py` (신규 생성)
- 4대 파라미터 정의 및 상세 정보
- 조건부 로직 규칙 (`ParameterRules` 클래스)
- API 응답 스키마

```python
from src.parameters import (
    get_parameters_definition,  # 파라미터 정의 조회
    ParameterRules,              # 유효성 검사 및 자동 설정
)
```

#### 2. `src/schema.py`
- `PurchasePlan` 모델에 4대 파라미터 필드 추가
- 타입 정의 (Literal 사용)
- `model_validator`를 통한 자동 검증

#### 3. `server.py`
새로운 API 엔드포인트:

```python
GET  /parameters                          # 파라미터 정의 조회
POST /parameters/available_bidding_methods  # 선택 가능한 입찰방법 조회
POST /parameters/available_winner_methods   # 선택 가능한 낙찰자결정방법 조회
POST /parameters/validate                   # 파라미터 조합 유효성 검사
```

### 프론트엔드 (React/TypeScript)

#### `frontend/src/app/page.tsx`

**새로운 기능:**
1. 파라미터 정의를 서버에서 가져와 상태로 관리
2. 4대 파라미터 선택 UI (Select 컴포넌트)
3. 낙찰자결정방법 변경 시 입찰방법 자동 업데이트
4. 소액수의 선택 시 입찰방법 필드 비활성화

## 💻 사용 예시

### 시나리오 1: 소액수의 계약

```typescript
// 사용자가 낙찰자결정방법을 '소액수의'로 선택
winner_determination: "소액수의"

// 자동으로 입찰방법이 '수의계약'으로 설정됨
bidding_method: "수의계약"  // 자동 설정, 비활성화
```

### 시나리오 2: 적격심사 계약

```typescript
// 사용자가 낙찰자결정방법을 '적격심사'로 선택
winner_determination: "적격심사"

// 입찰방법 선택 가능 (수의계약 제외)
bidding_method: "제한경쟁"  // 또는 "일반경쟁", "지명경쟁"
```

## 🧪 테스트 방법

### 1. 서버 재시작
```bash
python server.py
```

### 2. 파라미터 정의 확인
```bash
curl http://localhost:8000/parameters
```

### 3. 프론트엔드에서 확인
1. PDF/HWP 업로드
2. "🎯 4대 파라미터 설정" 섹션에서 값 변경
3. 낙찰자결정방법을 '소액수의'로 변경 → 입찰방법이 자동으로 '수의계약'으로 변경되고 비활성화되는지 확인
4. 낙찰자결정방법을 '적격심사'로 변경 → 입찰방법 선택 가능해지는지 확인

## 📂 파일 구조

```
sungver/
├── src/
│   ├── parameters.py          # 🆕 4대 파라미터 중앙 관리
│   ├── schema.py              # ✏️ 파라미터 필드 및 검증 로직
│   ├── nodes/
│   │   └── writer.py          # writer에서 parameters.py 활용 가능
│   └── config.py
├── server.py                  # ✏️ 파라미터 API 엔드포인트 추가
└── frontend/src/app/
    └── page.tsx               # ✏️ 4대 파라미터 선택 UI 추가
```

## 🎯 향후 확장 가능성

1. **법령 문구 자동 생성**: `writer.py`에서 `parameters.py`의 정보를 활용하여 계약법 구분에 따라 법령 문구 자동 변경
2. **계약 유형별 템플릿**: 계약 유형에 따라 다른 공고 템플릿 적용
3. **유효성 검사 강화**: 예산 금액에 따른 낙찰자결정방법 자동 제안
4. **이력 관리**: 사용자가 선택한 파라미터 조합 저장 및 재사용

## ⚠️ 주의사항

1. **필수적인 조건부 로직**: 소액수의 선택 시 반드시 수의계약이어야 법적으로 유효합니다.
2. **validator 순서**: Pydantic의 `model_validator`는 모든 필드 검증 후 실행되므로 전체 모델 검증에 적합합니다.
3. **프론트엔드 동기화**: useEffect를 통해 서버의 조건부 로직과 프론트엔드 UI가 동기화되도록 구현했습니다.
